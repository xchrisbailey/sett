# Fork of gpui-kit-markdown-editor

- Upstream: https://github.com/wabzqem/gpui-kit-markdown-editor
- Base version: 0.2.0 (crates.io)
- License: Apache-2.0 (see `LICENSE-APACHE`)
- Package name `gpui-kit-markdown-editor` and lib name `markdown_editor` are unchanged.

Every patched spot is marked with a `FORK` comment. The fork names the `[[…]]` syntax "wiki-link" in its API (`WikiLinkDirectory`, `WikiLinkClicked` and so on); the app and its glossary call it a Link. `tests/round_trip.rs` and `tests/fixtures/` cover what we rely on.

## Patches we carry

Each line is a candidate for upstreaming.

- **gpui-kit 0.9.1 build fix** (`direct.rs`): sets `task_marker: None` on `BlockNode::ListItem`. Without it the crate doesn't compile against gpui-kit ^0.9.1.
- **Final newline** (`import.rs`, `document.rs`, `serialize.rs`): an odd trailing line ending is kept as trivia (`EditorDocument::final_line_ending`) and no longer becomes an empty paragraph. Before, every save added a `\n`.
- **Wiki-links** (`markdown_source.rs`): `[[target]]`, `[[target|label]]` and `[[target#heading]]` are written unescaped, when their inner text needs no escaping. In table cells the `|` is still escaped. Before, they were saved as `\[\[…\]\]`, which breaks the link for other tools.
- **Soft line breaks** (`import.rs`, `serialize.rs`, `command.rs`, `state.rs`): gpui-kit's parser folds soft breaks into spaces. A parse-only inline plugin claims text nodes that contain line endings, and the importer turns each break into an `editor-soft-break` atom. The atom shows as a space and saves as the original line ending. The editor's own block copy and paste keeps the breaks, an inline copy writes them as spaces, and external pastes are unchanged. Before, hard-wrapped paragraphs, quotes and list items were joined into one line.
- **List markers** (`kind.rs`, `import.rs`, `serialize.rs`, `transaction.rs`, `command.rs`): `BlockKindData::List` records its bullet (`-` `*` `+`) or ordered delimiter (`.` `)`). Adjacent lists merge only when their markers match, because in Markdown they are separate lists. Before, every list was written with `-` or `1.`.
- **Callout markers** (`markdown_source.rs`): a `[!TYPE]` marker at the start of a paragraph is written unescaped (`> [!NOTE]`). Before, it was saved as `\[!NOTE\]`. The one exception is a top-level plain quote whose first line is just a Callout marker, which came from an escaped `\[!NOTE]`. That marker stays escaped (`serialize.rs`), so the quote doesn't become a Callout on the next load.
- **Callouts** (`kind.rs`, `import.rs`, `serialize.rs`, `command.rs`, `state.rs`, `direct.rs`): `BlockKindData::Blockquote` carries `callout: Option<Callout>` (public as `BlockKind::Blockquote { callout: Option<CalloutKind> }`). The importer makes a top-level quote a Callout when its first line is just `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` (any case). The marker and its line break leave the text, and the marker is kept as written. It doesn't use gpui-kit's `block_surface`, whose `Surface` nodes import as `Unknown` and save as nothing. The serializer writes the marker line, then the contents straight after it (a blank `>` line only when the first block can't follow a paragraph line, such as a rule or a list whose first item is empty). `EditorCommand::SetCallout` and `InsertCallout` set and create them; `InsertCallout` is refused below the top level, where the Insert Menu hides its callout options. Before, a callout was a plain quote with the marker as text.
- **Insert Markdown and pasted Callouts** (`command.rs`, `import.rs`, `insert_menu.rs`, `state.rs`): `EditorCommand::InsertMarkdown(text)` wraps the editor's own block paste (`paste_block_markdown`, `own = true`), so an Insert Menu option can hold a Template. A one-paragraph body now inserts (the own paste no longer returns `Ok(false)` for it). Like `InsertCallout` it is refused below the top level (it shares `can_insert_callout`), and `insert_menu_matches` hides its options there. Pasted top-level quotes now run `detect_callout`, so `> [!NOTE]` pasted as blocks, including the editor's own Callout copy, stays a Callout instead of saving as `> \[!NOTE]`; a quote pasted below the top level stays plain. Before, only a load detected Callouts.
- **Drawing callouts** (`callout.rs`, `color.rs`, `element.rs`, `frame.rs`, `state.rs`, `kind.rs`, `direct.rs`, `lib.rs`, `assets/icons/`): a top-level Callout is drawn as a tinted box with a 3px coloured left edge and a header row (Lucide icon, type name, a muted chevron), its blocks rendered inside with `BlockNode::render`. Every child is rendered, so an empty callout keeps its caret line. The header is labelled "<Type> callout", and its bounds are recorded in `FrameLayout::callout_headers` each frame; `BlockEditorState::callout_header_at` hit-tests them. The header text is darkened (or lightened, on a dark page) until it reaches 4.5:1 on the tint. A quote that isn't top level draws as a plain quote. It doesn't use gpui-kit's `Surface` node, which draws nothing for an empty callout and can't tell callouts apart.
- **Callout icon and colour, public** (`callout.rs`, `lib.rs`): `callout::icon` and `callout::color` are `pub`, re-exported as `callout_icon` (the type's Lucide SVG bytes, for `Icon::data`) and `callout_color`, so a Card on the Board (`crates/app`) draws the same icon in the same colour as the editor's header.
- **Link chips** (`wiki_chip.rs`, `wiki_link.rs`, `direct.rs`, `projection.rs`, `frame.rs`, `element.rs`, `state.rs`, `markdown_source.rs`, `lib.rs`, `assets/icons/file-text.svg`): a `[[slug]]` Link is drawn as a chip (document icon and the target's title; the label if there is one; "Title › Heading" with a heading; a dashed danger outline for a broken Link; a warning dot for an ambiguous one). The model keeps the text, so saving, copying, pasting, undo and the IME never see the chip. Only the projection swaps a closed span for an inline object named `sett-wiki-chip`. Spans come from `chip_spans`, which uses the serializer's `wiki_link_spans` (now `pub(crate)`) so "shows as a chip" and "saves bare" are one decision; it skips `code` and link runs and spans split across mark runs. A span is open while a selection end lies strictly inside it or the IME marked range overlaps it, worked out in `BlockEditorState::snapshot`; an open span stays text with a `code` mark in the projection only (no edit, `Changed`, undo step or autosave). `NodeCache::set_open` and `ProjectionCache::snapshot` key on it so the old and new leaf rebuild. Each leaf with chips has a `ChipMap` (`LeafInfo::chips`) converting model offsets to the renderer's, where a chip is one `U+FFFC` (3 bytes); offsets inside a closed span snap to the nearer edge. It is applied in `LeafGeom::index`, `offset_at` and `atom_at` and in selection painting (`element.rs`, widened to whole chips). `LeafGeom::chip_at` reports the chip under a point and `atom_at` never does. The host gives titles and states with `BlockEditorState::set_wiki_links(Arc<WikiLinkDirectory>, cx)` and reads which slugs to look up with `wiki_link_slugs()`; a slug missing from the directory draws as broken. The plugin reads the directory through a shared handle each frame. Before, `[[slug]]` was plain text.
- **Following Links** (`wiki_chip.rs`, `wiki_link.rs`, `state.rs`, `element.rs`, `frame.rs`): Cmd/Ctrl-click on a Link chip, found with `LeafGeom::chip_at`, emits `BlockEditorEvent::WikiLinkClicked { slug, heading }` and leaves the caret alone (`follow_link_at` still handles URLs and runs first). While the modifier is held over a chip, `hover_at` (also run when the modifier changes) records which chip in a shared `HoverHandle`, keyed by leaf and span start; the plugin draws that chip darker and underlined, with a hand pointer, unless it is broken: a broken one gets the arrow pointer and a "No Item has the slug `x`" tooltip. `BlockEditorState::reveal_heading(text, cx)` puts the caret at the start of the first heading whose text matches, ignoring case, and scrolls to it; it returns whether one was found. The keyboard route is `cmd-alt-enter` (`ctrl-alt-enter` elsewhere; plain `cmd-enter` is `ExitBlock`): the `FollowWikiLink` action emits the same event for the Link whose span holds the caret or has it at an edge, and propagates anywhere else. The editor never opens anything itself.
- **Link chip editing** (`command.rs`, `state.rs`, `element.rs`, `frame.rs`): Backspace with the caret right after a closed chip, or Delete right before one, removes the whole `[[…]]` span in one transaction (`delete_as`, via `chip_spans`); inside an open chip they delete one character. A plain single click on a chip (`LeafGeom::chip_at`) places the caret at the nearer edge on press, so a drag never starts inside, and `release_chip` moves it just before `]]` (opening the chip) if the press was not a drag. Cmd/Ctrl-click is untouched.
- **Table delimiter row** (`kind.rs`, `import.rs`, `serialize.rs`, `table.rs`): the source's delimiter row (`|------|`) is kept for as long as it still matches the columns and their alignment. Before, it was always rewritten to `| --- |`.
- **Adaptive tables** (`element.rs`): the render style sets `overflow.x: scroll` on gpui-kit's table style. In its default wrap mode a column shrinks to 4rem however long its words are, so in a narrow editor cell text broke mid-word ("Estimat / e", #49). Now a column stops at a floor scaled to its content and the table scrolls sideways below that.
- **Insert Menu** (`insert_menu.rs`, `menu.rs`, `state.rs`, `element.rs`, `lib.rs`): typing `/` as the only character of a paragraph opens a filterable list of block types under it. ↑/↓ move the highlight, Enter or Tab picks, Esc closes. Picking removes the typed `/query` and runs the option's `EditorCommand` as one undo step. Esc, a click outside, a query with no match, deleting the `/` or moving the caret away close it and leave the text alone. Text being composed with an IME is left out of the query, so the list holds still until it is committed. Hosts replace the options (`InsertMenuOption`) with `with_insert_menu_options` (an empty list turns the menu off), or at run time with `set_insert_menu_options`: an open menu keeps its rows and the new options apply the next time it opens. `InsertMenuOption::section(label)` groups options: unsectioned ones come first, then each section in order of first appearance, with a muted `text_xs` header before its first visible option and a divider above it when rows come before. A header isn't an option, so the highlight and ↑/↓ never land on it (`insert_menu::rows` lays them out). `key_context` now builds its string, so the `insert_menu` context can combine with the others.
- **Callout type menu** (`callout_menu.rs`, `menu.rs`, `callout.rs`, `command.rs`, `state.rs`, `element.rs`, `assets/icons/check.svg`): a click on a Callout's header, or `cmd-alt-c` (`ctrl-alt-c` elsewhere) with the caret in one, opens a "Callout type" list under the header: the five types (coloured icon, name, ✓ on the current one), a divider, then "Plain quote". ↑/↓ move the highlight (wrapping), Enter or Tab picks, Esc or a click outside closes; the highlight starts on the current type. Picking retypes that quote as one undo step through `BlockEditorModel::retype_quote`, which `SetCallout` now also uses, so the caret never moves. Outside a callout the shortcut propagates; with the header scrolled out of view (or not yet drawn) it opens nothing. Any edit, caret move or blur closes it. The header is now a `Button` role with a tooltip naming the shortcut. It is not a tab stop: the editor owns a single focus, so the keyboard route is the shortcut (#19), an exception to `CODING_STANDARDS.md`'s rule that everything clickable is focusable and opens on Enter. Its keys sit in a `callout_menu` key context, registered last.
- **Link Picker** (`link_picker.rs`, `menu.rs`, `state.rs`, `element.rs`, `lib.rs`): typing `[[` in a text block, outside inline code and code blocks, opens a list of the host's `LinkCandidate`s (set with `set_link_candidates`) under the `[[`. The text after it filters by title or slug, ignoring case: title prefixes first, then other matches, most recently changed first within each. ↑/↓ move the highlight (wrapping, skipping rows with `reachable: false`), Enter or Tab or a click picks, Esc closes. Picking replaces the typed `[[query` with `[[slug]]` as one undo step and puts the caret after it. Esc, typing `]]`, a caret move past the query, a caret move before the `[[`, or blur close it and leave the text alone; text being composed with an IME is left out of the query. With no match it stays open and says "No matching Items". When no row can be picked, Enter and Tab close it and act as they would without it. Its keys sit in a `link_picker` key context, registered last. Unfinished `[[query` text is saved escaped (`\[\[query`), like any other brackets that aren't a complete Link.
- **Link Picker, Create Note** (`link_picker.rs`, `state.rs`): while the trimmed query is not empty and no candidate's title equals it (ignoring case), the picker ends with a row `Create Note "<query>"`, which replaces "No matching Items" when nothing matches. Picking it closes the picker and emits `BlockEditorEvent::CreateLinkTargetRequested { title }`. The host creates the Note and calls `BlockEditorState::complete_link_pick(slug, cx)`, which inserts `[[slug]]` as one undo step like a normal pick. If the host never answers, the typed text stays as it was.
- **Code Block copy and paste** (`code_clipboard.rs`, `state.rs`, `serialize.rs`): a copy from inside one Code Block puts the raw code on the clipboard (other apps are unchanged) and tags it (`CopyKind::Code`) with the block's `lang` and `meta`. Pasted into a Code Block it goes in raw; into a paragraph, one line is plain text with no Markdown parsing, and several lines become a Code Block with the tag's `lang` and `meta`, placed like `paste_blocks` places blocks. Text pasted into a Code Block that is exactly one closed fenced block (backticks or tildes) inserts only its code; the target keeps its language, or takes the pasted language (and meta) in the same undo step if it had none. Anything else, and plain paste, inserts raw. `selected_text` and `paste_text` now delegate to `BlockEditorModel::copy_selection` and `paste_clipboard` so tests run without GPUI. Before, such a copy was untagged, pasted into a paragraph as Markdown (`# x` became a heading), and fence lines pasted into a Code Block stayed in the code.
- **Code Block language lookup** (`language.rs`, `Cargo.toml`): `highlights(lang)` says whether a Code Block's language highlights, ignoring case. It copies gpui-component 0.9.1's alias table and three-step `find_syntax` (its `language_name` and `find_syntax`) over the same two-face syntax set, since gpui-kit doesn't export them; "Plain Text", `text`, `plain` and `plaintext` count as not highlighted. `CODE_BLOCK_LANGUAGES` is the curated list for the Language Menu, and `display_name(lang)` maps a fence name or alias to its display name. A drift test checks the lookup against outcomes recorded from gpui-kit's. Adds direct `syntect` and `two-face` dependencies, already compiled with these features.
- **Code Block language label** (`code_label.rs`, `element.rs`, `frame.rs`, `state.rs`, `lib.rs`): every Code Block shows a control in its top-right corner: the curated display name ("Rust" for `rs`), "Plain text" (fainter) for a bare fence, or an amber `warning` dot and the text as written when `highlights` says it won't; a language that highlights but isn't in the list shows as written. A chevron follows, hover is the ghost Button's background, and the tooltip is "Change language" with the `OpenLanguageMenu` shortcut (`cmd-alt-l`; the Language Menu handles it). **Patched, not redrawn:** gpui-base draws its own label inside `CodeBlock::render` and `RenderContext` can't switch it off, and `CodeBlock`'s state and language are private, so redrawing the block would mean copying its highlighting, scrolling and leaf wiring. Instead the block renders as before with `code_block.padding.top` raised to 28px (so blocks with no language keep the corner clear too), and a patch in the block's own background colour is painted over gpui-base's label, then our control on top. The patch is a full-width strip inside the block's border, as tall as that padding; if gpui-base's label moves, or a `code_block()` background refinement changes the block's fill, the patch needs to follow. The control is a `Button` role labelled "Language: <text>", not a tab stop (same exception as the Callout header, #19). Its bounds are recorded in `FrameLayout::code_labels` each frame; `BlockEditorState::code_label_at(point)` hit-tests them, and a click on one opens the Language Menu and leaves the caret alone.
- **Language Menu** (`language_menu.rs`, `menu.rs`, `command.rs`, `state.rs`, `element.rs`, `callout_menu.rs`, `lib.rs`): a click on a Code Block's language label, or `cmd-alt-l` (`ctrl-alt-l` elsewhere) with the caret in one, opens a popover under the label: a query line, Plain text, then the curated languages, the current one ticked through aliases. Typed text goes to the menu's own query (`OpenMenu::query`), not the code, and IME text still being composed is left out; Backspace edits the query. A last row `Use "<query>"` writes a language the list lacks. `set_code_lang` sets the language of a given block without moving the caret and keeps the meta; clearing the language drops the meta, and `set_code_block_info` now does too. The keys live under a `language_menu` key context, registered last; an edit, a caret move or blur closes it. It is custom rather than a `PopupMenu` for the same reason as the Insert Menu.
- **No `tree-sitter` feature** (`Cargo.toml`): removed. It added about 50 MB and replaces syntect outright; Code Blocks highlight through syntect, the default feature.
- **Custom menus** (`menu.rs`): the four menu slots (Insert, Callout, Language, Link) share one popover, option row and wrapping highlight, and the shared bounds lookup, in-view check, open and pick plumbing for the anchored menus. `popover` caps the height at 20rem (less if the window is shorter) and scrolls the rows inside it, with an optional fixed header (the Language Menu's query line). The rows get gpui-kit's vertical scrollbar, and while more lie below, a short fade over the bottom edge (macOS hides scrollbars at rest). Each `OpenMenu` owns its `ScrollHandle`, so a menu opens at the top; a key move (or a highlight that starts further down, such as the Language Menu's current language) scrolls the highlighted row into view on the next frame, while hover doesn't. The Link Picker and Language Menu used to scroll their own lists (18rem and 14.75rem caps); they now use this one. They are custom rather than gpui-kit's `PopupMenu` because focus has to stay in the editor (the caret, the Insert Menu's filtering and the menu keys all run through it), and a `PopupMenu` takes focus when it opens.
- **Our build only, not for upstream** (`Cargo.toml`, `tests/mod.rs`, `component.rs`, `state.rs`, `projection.rs`): the GPUI view tests are gated behind a `view-tests` feature, and the `gpui-kit/test-support` dev-dependency is dropped because it pulls in `gpui-fast`, whose pins don't resolve in our workspace. The crate uses the workspace `gpui-kit`, and upstream's `Cargo.lock` is removed.

## Known normalisations

A file using any of these is rewritten on its first save; after that, saves are stable.

- `__bold__` / `_italic_` → `**bold**` / `*italic*`. The delimiter would have to live on gpui-kit's `TextMark`.
- Hard breaks (two trailing spaces, `\` + newline) → `<br>` with the lines joined.
- `$` in text → `\$`. Escaping is decided per text run, but a math span can cross marks.
- Setext headings → ATX, and closing `##` are dropped.
- `~~~` fences → backticks; indented code → fenced code.
- Table cell padding → `| a | b |`. The delimiter row is kept, as above.
- A URL inside `( )` → `<url>`.
- A blank `>` line between a Callout's marker and its first paragraph, list, heading, code block or quote is dropped (`> [!NOTE]\n>\n> Body` → `> [!NOTE]\n> Body`).
- Trailing spaces before a soft break are dropped. CRLF line endings between blocks become LF.
- Unescaped `[[…]]` or `[!X]` text could become a link on reparse if a matching `[…]: url` definition exists. This is unlikely in practice.
